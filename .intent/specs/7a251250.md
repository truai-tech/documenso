# WhatsApp Notifications

## Intent

Give every user the choice to receive Documenso notifications via WhatsApp instead of, or in addition to, email — so that people who are more responsive on WhatsApp never miss a signing request or status update.

---

## Summary

Users with a Documenso account gain a **Notification Channel** preference in their account settings. They choose whether they want to receive all notifications by email, by WhatsApp, or by both. When WhatsApp is selected they enter and save their mobile phone number.

For document recipients who do not have a Documenso account, the sender can optionally enter the recipient's phone number in the document editor. Documenso then sends the recipient a WhatsApp message in addition to the standard email.

Every notification event that currently triggers an email also triggers a WhatsApp message where a phone number is available and the user's preference allows it.

---

## How It Works

### 1. Notification Channel preference (account holders)

A new **Notifications** section is added under **Settings → Profile**.

Users choose one of three options:

| Option | Behaviour |
|---|---|
| **Email only** | No change from today — all notifications arrive by email (default) |
| **WhatsApp only** | Notifications are sent via WhatsApp; no email is sent |
| **Email and WhatsApp** | Both channels are used for every notification |

When **WhatsApp only** or **Email and WhatsApp** is selected, a **Mobile phone number** field appears. The user enters their number in international format (country code + number). The number is saved to their account and used for all WhatsApp notifications they receive.

If a user selects a WhatsApp option but has not entered a phone number, their notifications continue to be sent by email until a valid number is saved.

### 2. Phone number for external recipients

When a sender adds a recipient in the document editor, an optional **Phone number** field appears on each recipient row. This field is only relevant for recipients who do not have a Documenso account (or whose account preference is unknown to the sender).

- If a phone number is entered, Documenso sends a WhatsApp message **in addition** to the standard email for that recipient.
- If the field is left blank, only email is sent — exactly as today.
- If the recipient does have a Documenso account, their own channel preference overrides whatever the sender enters.

Phone numbers for external recipients are stored per-document, not globally. They are not reused across documents unless the sender enters them again.

### 3. What the WhatsApp messages contain

WhatsApp messages are concise text notifications that mirror the key information from the corresponding email:

- **Signing invitation** — document name, sender name or organisation name, and a tap-to-open signing link unique to that recipient.
- **Signing reminder** — same content as the invitation, with "Reminder:" at the start of the message.
- **Recipient has signed** (to document owner) — name or email of the person who signed and the document name.
- **Bulk send complete** (to sender) — template name and a link back to Documenso.
- **Organisation member joined / left** (to org admins) — member name/email and organisation name.

The signing link in the WhatsApp message is identical to the one in the email — it is unique per recipient and expires when the document is completed or deleted.

### 4. Events covered

All notification events that currently generate an email are also supported over WhatsApp:

| Event | Who receives it |
|---|---|
| Signing invitation | The recipient being asked to sign, approve, or view |
| Signing reminder (automatic, recurring) | The recipient who has not yet acted |
| Recipient has signed / approved / viewed | The document owner |
| Document completed | All recipients (CC copy) |
| Document cancelled | All recipients |
| Bulk send complete | The sender |
| Organisation member joined | Organisation admins |
| Organisation member left | Organisation admins |

### 5. Fallback behaviour

- If WhatsApp delivery fails for any reason (invalid number, delivery error), Documenso falls back to email and logs the failure.
- If a user has set **WhatsApp only** but a phone number is not saved, email is used as a fallback until the number is provided.

### 6. Provider setup (admin)

A WhatsApp Business API provider (e.g. Meta Cloud API or Twilio) must be configured by the instance administrator before WhatsApp notifications can be sent. This requires:

- A registered WhatsApp Business phone number
- An approved set of message templates from Meta
- API credentials entered in the platform's environment configuration

Until a provider is configured, the WhatsApp channel option is hidden from user settings and no WhatsApp messages are sent.

## Included / Not Included

**Included**
- Notification channel preference (Email only / WhatsApp only / Both) in user account settings
- Phone number field on each recipient in the document editor
- WhatsApp delivery for all existing notification events
- Automatic reminders via WhatsApp on the same schedule as email reminders
- Fallback to email when WhatsApp delivery is not possible
- Provider configuration for the instance administrator

**Not Included**
- Two-way WhatsApp conversations — recipients cannot reply via WhatsApp to take actions
- WhatsApp-only recipients — an email address remains required for all recipients
- Notification channel preferences at organisation or team level — each user manages their own
- In-app or push notifications — out of scope for this feature
- Custom WhatsApp message templates per document or organisation — all events use a single approved template set
