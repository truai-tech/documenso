# WhatsApp Notifications via Meta Cloud API

## Intent

All document event notifications today are delivered exclusively by email. Some users — particularly in mobile-first workflows — respond faster to WhatsApp messages. This feature adds WhatsApp as a parallel notification channel, opt-in per user, using the Meta Cloud API.

## Summary

Users can optionally enable WhatsApp notifications in their profile settings by providing a phone number. Once enabled, every document event that already triggers an email also sends a WhatsApp message to that user. Email and WhatsApp run in parallel — neither replaces the other.

## How It Works

### User configuration (Profile Settings)

A new **WhatsApp Notifications** section appears on the Profile settings page (`Settings > Profile`). It contains:

- A **phone number field** (international format, e.g. +49 151 12345678)
- A **toggle** to enable or disable WhatsApp notifications
- A **verify** step: after entering a number, the user receives a WhatsApp confirmation message with a code they must enter before notifications go live. This prevents phantom numbers being saved.

The phone number and enabled/disabled state are stored on the user record. The number is only used for WhatsApp notifications — it is never shown to other users or recipients.

### Notification delivery

Every event that sends an email to a user also checks whether that user has WhatsApp notifications enabled and a verified phone number on file. If both are true, a WhatsApp message is dispatched in parallel via the Meta Cloud API.

The covered events are the same nine already controlled by the email settings:

| Event | Recipient of WhatsApp message |
|---|---|
| Signing request | The recipient being asked to sign |
| Recipient signed | The document owner |
| Document pending (still awaiting others) | The recipient who just signed |
| Recipient removed from pending document | The removed recipient |
| Document completed (recipient copy) | All recipients |
| Document completed (owner copy) | The document owner |
| Pending document deleted | All recipients |
| Document created from direct template | The document owner |
| Recipient signing window expired | The document owner |

### Message content

WhatsApp messages are short, text-only notifications. Each message includes:

- The document title
- A description of the event (e.g. "John Doe has signed your document")
- A direct link to the relevant page in Documenso

Messages are sent in the user's configured interface language where a matching WhatsApp message template is available; English is the fallback. All message templates must be pre-approved by Meta before use.

### Meta Cloud API integration

Documenso connects to the Meta Cloud API using a configured phone number ID and a permanent access token stored in server-side environment variables. Message delivery is fire-and-forget within the existing background job for each event — a WhatsApp failure does not block or retry the email. Delivery errors are logged for observability.

## Included / Not Included

**Included**
- Phone number input and verification flow in Profile settings
- Per-user opt-in toggle (on/off)
- WhatsApp message dispatch for all nine existing notification events
- Parallel delivery alongside email (WhatsApp does not replace email)
- Server-side Meta Cloud API configuration via environment variables

**Not Included**
- Per-event granular toggle (users enable all or none — mirroring the initial email default; per-event control can come later)
- Team- or organisation-level WhatsApp configuration
- WhatsApp as a document distribution method (i.e. sending signing links exclusively via WhatsApp instead of email)
- Two-way WhatsApp interactions (replies, signing via WhatsApp)
- Recipient-side WhatsApp notifications (only Documenso account holders with a configured number receive WhatsApp messages)
