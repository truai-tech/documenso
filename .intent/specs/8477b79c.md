# AI Field Placement — Suggestion Review

## Intent

Generating AI suggestions is only useful if the sender can quickly understand what was proposed, trust what looks right, and fix what doesn't. The review flow turns the raw suggestion set into a controlled editing experience: the sender stays in charge and the document editor remains the single source of truth for fields — AI suggestions only become real fields when the sender explicitly accepts them.

---

## Summary

After AI analysis completes, the document editor's field canvas enters a **suggestion review mode**. Pending suggestions are overlaid on the PDF as distinct, colour-coded ghost fields. A compact review panel lists all suggestions by recipient. The sender can accept, reject, or adjust each suggestion individually, or accept all at once. Accepted suggestions are converted into real editable fields using the existing field creation path. The sender can also fall back to purely manual placement at any time.

---

## How It Works

### Entering review mode

Review mode activates automatically when a completed suggestion set is available and the sender is on the field-placement step. A banner or callout at the top of the field canvas reads:

> **"AI suggested N fields — review before adding them."**

A count badge on the "Suggest fields with AI" button also updates to reflect outstanding suggestions.

If the sender navigates away from the field step and returns, the suggestions are still present (they are stored server-side against the document) and review mode reactivates.

### Visual representation of suggestions on the canvas

Each pending suggestion is drawn on the PDF canvas as a **ghost field**:

- Semi-transparent fill using the assigned recipient's colour (matching the existing colour scheme for recipient-coded real fields).
- A dashed border distinguishing it from a confirmed real field (real fields have a solid border).
- A small **field-type icon** inside the ghost (e.g. pen icon for Signature, calendar icon for Date).
- A **recipient chip** showing the assigned recipient's initials, matching the existing recipient avatar styling.
- A confidence badge: a small dot or icon that is green (high), amber (medium), or grey (low), visible on hover or when the ghost is selected.

Ghost fields are non-interactive for signing purposes; they are only interactive for review actions.

### Review panel

A collapsible **AI Suggestions** sidebar panel (or an inline section within the existing field sidebar) lists all pending suggestions, grouped by recipient. Each row shows:

- Field type label (e.g. "Signature", "Date", "Text").
- Page number and approximate position (e.g. "Page 2, top-right").
- Confidence indicator.
- Two inline action buttons: **Accept** (checkmark) and **Reject** (×).

The panel also shows:
- A **"Accept all"** button that accepts every remaining pending suggestion in one action, with a count ("Accept all 12").
- A **"Reject all"** button that discards the entire suggestion set.
- A summary count: "3 accepted · 1 rejected · 8 pending".

Clicking a row in the panel scrolls the PDF canvas to the relevant page and highlights (pulses) the corresponding ghost field.

### Interacting with individual suggestions

**Accepting a suggestion:**
- The sender clicks the Accept button on the panel row, or clicks the ghost field on the canvas and selects Accept from the field's context menu.
- The ghost field converts immediately into a real, editable field in the editor — it gets a solid border, recipient colour, and behaves like any manually placed field.
- The field is saved using the existing autosave path.
- The row is removed from the suggestions panel.

**Rejecting a suggestion:**
- The sender clicks the Reject button, or clicks the ghost field and selects Reject.
- The ghost field disappears from the canvas.
- The row is struck through briefly then removed from the panel.

**Adjusting before accepting:**
- The sender can drag a ghost field to a new position on the canvas before accepting it. The ghost moves with the drag but remains a ghost (dashed border) until explicitly accepted.
- The sender can resize a ghost field using the standard resize handles.
- The sender can reassign the ghost to a different recipient by clicking the recipient chip and selecting a new recipient.
- After any adjustment, the ghost still requires an explicit Accept action to become a real field.

**Editing a suggestion's field type:**
- The sender can change the suggested field type (e.g. from Text to Name) via a dropdown that appears in the ghost field's context menu or in the panel row. The ghost updates its icon accordingly.

### "Accept all" behaviour

When the sender clicks **Accept all**:
1. All pending (not yet rejected) ghost fields are accepted simultaneously.
2. They all convert to real fields in one batch save operation.
3. The suggestions panel closes and the banner disappears.
4. A toast confirms: "12 fields added successfully."

If the batch save partially fails (e.g. some fields land outside page bounds after normalisation), the failed fields remain as ghosts with an error indicator and a message prompts the sender to review them.

### Exiting review mode

Review mode ends when:
- All suggestions have been accepted or rejected (the panel closes automatically).
- The sender clicks **"Dismiss suggestions"** — this rejects all remaining suggestions and closes the panel. A confirmation prompt appears if there are 5 or more pending suggestions remaining.
- The sender replaces the PDF (suggestion set is discarded).

After exiting, the editor returns to the standard manual field-placement mode. The sender can still trigger a new AI analysis if they want a fresh set of suggestions.

### Interaction with manually placed fields

Existing manually placed fields are always shown with solid borders and are unaffected by the suggestion review state. The sender can add, move, or delete manual fields at any time during review mode. Manual fields and accepted-suggestion fields are identical once created.

### Undo

Accepting or rejecting a suggestion can be undone with the standard Ctrl/Cmd+Z undo gesture, up to the typical undo stack depth. This follows the existing undo model for field add/remove in the editor.

## Included / Not Included

**Included**
- Ghost-field overlay on the PDF canvas for all pending suggestions.
- Confidence indicators on ghost fields and in the review panel.
- Per-suggestion accept, reject, drag-to-reposition, resize, recipient reassignment, and field-type change.
- "Accept all" and "Reject all" batch actions.
- Inline review panel grouped by recipient with scroll-to-field linking.
- Undo support for individual accept/reject actions.
- Persistence of unreviewed suggestions when the sender navigates away and returns.

**Not Included**
- Bulk editing of field metadata (labels, validation rules) through the review panel — these are configured in the standard field settings panel after acceptance.
- Suggestion explanations or reasoning text from the AI model displayed in the UI.
- Tracking or analytics on acceptance rates per document type (may be addressed separately).
- Review mode on the recipient signing page — suggestions are a sender-only, pre-send concept.
